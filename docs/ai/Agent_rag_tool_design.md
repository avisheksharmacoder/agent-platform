# Agent RAG Tool Design

## Overview
This document details the design and implementation strategy for integrating a Retrieval-Augmented Generation (RAG) vector search tool into our primary AI assistant (`chat_agent`). 

When a user submits a problem, we want the AI agent to be capable of checking our vector database (Qdrant) for similar, previously resolved tickets. If the AI finds a matching resolution, it can provide the solution directly to the user instead of unnecessarily creating a new ticket.

## Core Components

### 1. Dependency Injection (`ChatDependencies`)
To perform a database search, the `chat_agent` needs access to the vector database connection. Because the agent's tool functions are isolated, we must pass the database instance to the agent when we run it.
- We will define a Pydantic-AI `dataclass` called `ChatDependencies`.
- This dataclass will hold a reference to `vector_db`.
- The `chat_agent` will be configured with `deps_type=ChatDependencies`.
- When calling `chat_agent.run(...)` inside `nemotron_router.py`, we will construct and pass this dependency object, pulling the database from the FastAPI `request.app.state`.

### 2. Generating Embeddings via the Existing Router
Before searching the vector database, the user's problem description must be converted into a mathematical vector (an embedding). 
- Instead of setting up a new Ollama client inside the agent, we will reuse our existing, proven logic.
- We will import `generate_embedding` and `EmbeddingRequest` from `src.v1.embedding_router`.
- The agent's tool will call this Python function natively, passing the problem description, and receiving the embedding vector in return.

### 3. The Tool Function (`search_knowledge_base`)
The tool itself will be an asynchronous Python function attached to the agent using the `@chat_agent.tool` decorator. 
- **Input**: A single string argument `problem_description` (generated by the LLM based on the user's chat).
- **Execution**: 
  1. Calls the `generate_embedding` function natively with the `problem_description`.
  2. Extracts the returned `embedding` vector from the response.
  3. Queries the vector database (`ctx.deps.vector_db.search_similar_documents(embedding)`).
- **Output**: Returns a `RAGDocumentSourceOut` model, which is a structured list of `RAGDocumentSource` objects (containing the IDs, titles, contents, and embeddings of matching past tickets).

## Step-by-Step Implementation

1. **Update `agent.py`:**
   - Import necessary Pydantic models (`RAGDocumentSourceOut`, `RAGDocumentSource`).
   - Import `generate_embedding` and `EmbeddingRequest` from `embedding_router`.
   - Create the `ChatDependencies` dataclass.
   - Update `chat_agent = Agent(..., deps_type=ChatDependencies)`.
   - Write the `@chat_agent.tool` function (`search_knowledge_base`) as per the execution steps above.

2. **Update `nemotron_router.py`:**
   - Add the FastAPI `Request` object to the `/generate` endpoint parameters.
   - Extract `vector_db = request.app.state.vector_db`.
   - Pass the dependency when executing the agent: `await chat_agent.run(history_str, deps=ChatDependencies(vector_db=vector_db))`.
